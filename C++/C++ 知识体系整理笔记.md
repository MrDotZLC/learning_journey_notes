## C++ 三大特性

### 封装
- 将数据与操作行为结合，形成独立对象。
- 通过接口隐藏实现细节，增强安全性与复用性。

### 继承
- 子类继承父类成员，可复用父类属性与方法。
- 分为单继承、多重继承、菱形继承（虚继承解决冲突）。

### 多态
- 同一接口，不同实现。
- 分为静态多态（模板、重载）与动态多态（虚函数）。

## 结构体与共同体

### struct
- 各成员独立存储，`sizeof(struct)` 为成员之和（含内存对齐）。

### union
- 所有成员共用同一内存，仅存放一个成员的值。

## 内存与存储结构

```
高地址
│ 栈（stack）
│ 堆（heap）
│ bss 段（未初始化全局变量）
│ data 段（已初始化全局变量）
│ text 段（代码区）
低地址
```

- 栈：局部变量、函数调用帧。
- 堆：动态内存分配。
- data + bss：静态存储区。

## static 与 const

### static
- 局部静态变量：函数退出后仍保存值。
- 全局静态变量/函数：仅文件内可见。
- 类内静态成员：全对象共享。

### const
- 修饰变量：不可修改。
- 修饰函数：保证成员函数不改动成员变量。

> `static` 与 `const` 不能同时修饰成员函数。

## C++ 初始化与线程安全

- C 语言：静态变量编译时初始化。
- C++：引入**运行时初始化**（首次调用时构造）。
- C++11 保证局部静态变量初始化 **线程安全**。

## 指针、引用与 const

### 指针
- 可为空，可多级，指向地址。

### 引用
- 本质是编译期语法糖，底层实现为常量指针。
- 不能为 null，必须初始化。

### const 与指针关系

## this 指针

- 隐含于每个非静态成员函数中，指向当前对象。
- 存放位置依编译器实现，可位于寄存器或栈中。
- 不可在构造函数中 delete this。

## inline 内联函数

- 在调用处展开，减少函数调用开销。
- 具备类型检查，安全性高于宏。
- 虚函数在运行期不具备内联特性。

## struct 与 typedef struct

- C 中 `typedef struct {...} Name;` 可省略 `struct` 关键字。
- C++ 中直接 `struct Name {...};` 即可。

## explicit 关键字

- 修饰单参数构造函数，禁止隐式类型转换。
- 防止隐式调用导致的意外构造。

## friend 友元机制

- 友元函数/类可访问类的私有成员。
- 提高性能但破坏封装性。
- 常用于：运算符重载（如 `operator<`）。

---

## 虚函数与多态

- 动态多态依赖**虚函数表（vtable）**与**虚表指针（vptr）**。
- 构造函数不能为虚函数；析构函数应设为虚函数（防止内存泄漏）。
- 友元、静态成员函数不能为虚函数。

**性能代价**：
- 每对象多一个 vptr；
- 每次虚函数调用需查表一次。

## SLAM（同时定位与建图）

### 概念
SLAM（Simultaneous Localization and Mapping）让机器人在未知环境中**定位自身并构建地图**。

### 组成
1. 定位（Localization）—— 计算自身位姿。
2. 建图（Mapping）—— 根据传感器数据绘制环境。

### 常见类型
| 类型 | 传感器 | 特点 |
|------|---------|------|
| 激光雷达 SLAM | LiDAR | 精度高，成本高 |
| 视觉 SLAM | 摄像头 | 成本低，信息丰富 |
| 惯性 SLAM | 摄像头 + IMU | 抗干扰、稳定性高 |
| 多传感器 SLAM | 融合多源 | 精度最高 |

### 框架
- ORB-SLAM2 / 3：视觉 SLAM 标准方案。
- LIO-SAM：激光 + IMU 自动驾驶方案。
- Cartographer：Google 开源激光 SLAM。

### 应用
- 自动驾驶定位
- 扫地机器人
- 无人机导航
- AR/VR 空间定位

### SLAM 流程
1. 传感器数据采集
2. 特征提取与匹配
3. 位姿估计
4. 地图更新
5. 闭环检测
6. 图优化（Graph Optimization）

### 小结
SLAM 是机器人智能化的基础，其未来方向是 **多传感器融合 + 深度学习增强 SLAM**。
