## **0. 模型加载（Model Loading）**
推理开始前，需要先加载模型权重。[大模型加载流程与关键技术](%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%8A%A0%E8%BD%BD%E6%B5%81%E7%A8%8B%E4%B8%8E%E5%85%B3%E9%94%AE%E6%8A%80%E6%9C%AF.md)
### **0.1 权重加载（Weights Loading）**
- 模型文件通常是：
    - `.bin`（GPT-2 风格）
    - `.pt` / `.pth`（PyTorch）
    - `safetensors`
    - GGUF（llama.cpp 推理格式）
- 权重通常是压缩/量化格式：
    - FP16
    - BF16
    - FP8
    - INT8
    - INT4（GGML）
- 加载方式需要：
    - 将权重映射到 GPU 内存（zero-copy）
    - 构建计算图（部分框架会 JIT）
### **0.2 KV Cache 初始化**
KV 缓存存储：
- **K（Key）张量**
- **V（Value）张量**
    用于后续加速解码。
在 decode 阶段，模型不会重复计算整个序列，而是：
- 只对当前 token 做一次前向传播
- 历史 token 的 K/V 存在 cache 中直接复用
## **1. 输入处理（Preprocessing）**
### **1.1 Prompt 模板拼接**
`<s>[INST] 你现在是... [/INST]`
LLM 推理系统（如 OpenAI / Llama-3 tokenizers）会自动包装 prompt。
### **1.2 Tokenization（分词）**
常用算法：
- BPE（GPT）
- SentencePiece（LLaMA）
- Unigram（T5）

Tokenization 细节：
- 词表一般大小：32k–100k
- 最长 token 匹配（贪心）
- 空格独立编码（GPT 模型）
结果：
`text → token_ids → int32 list`

## **2. Embedding 层**
### **2.1 Token Embedding Lookup**
[Token Embedding 介绍](../Transformer/Token%20Embedding%20介绍.md)
将 token IDs 转为向量：
`embedding[token_id] → R^d  (如 d=4096)`
### **2.2 Positional Encoding / RoPE**
[Positional Encoding 位置编码介绍](../Transformer/Positional%20Encoding%20位置编码介绍.md)
Transformer 不具备序列顺序，因此需要位置编码。
目前主流：
#### **RoPE（旋转位置编码）**
对 Q、K 进行二维旋转：
`Q_rot[i] = Q[i] * cos(θ) + Q[i+1] * sin(θ) K_rot[i] = K[i] * cos(θ) + K[i+1] * sin(θ)`
- 支持 extrapolation
- 适合长序列
- LLaMA, GPT-J, GPT-NeoX 都用
## **3. Prefill（Prompt 上下文编码）**
- **输入**：Embedding + Positional Encoding
- **操作**：
    - 对整个 prompt embedding 执行 Transformer decoder 层前向传播
    - 每层计算 Q/K/V → Attention → FFN → LayerNorm
    - 每个 token 的 K/V 存入 KVCache
- **输出**：
    - 每层隐藏状态（hidden states）
    - KVCache（每层每个 token 的 K/V）
**特点**：
- 全序列并行计算，提高效率
- 为 Decode 阶段提供上下文信息，避免重复计算历史 token
**流程示意**：
```
Prompt token_ids
    ↓ Embedding + Positional Encoding
    ↓ Prefill (全序列 Transformer decoder 前向传播)
Hidden States + KVCache filled
```
**关系与 Decode**：
- Prefill 可以看作 **一次性走完 Decode 流程，但处理整个 prompt token**
- Decode 阶段只处理新生成 token，利用 Prefill 填充的 KVCache 高效生成
## **4. Transformer Block（核心）**
[🚀 Transformer解析](../Transformer/🚀%20Transformer解析.md)
每层包括：  
**Attention → MLP → 残差 → LayerNorm**
### 🧠 **4A. Self-Attention（自注意力）**
[注意力和自注意力（Attention vs Self-Attention）](../Transformer/注意力和自注意力（Attention%20vs%20Self-Attention）.md)
#### **4A.1 线性变换得到 Q、K、V**
对输入 X 执行 3 个矩阵乘法：
`Q = X W_Q K = X W_K V = X W_V`
其中：
- `X` shape: (batch, seq_len, d_model)
- Q/K/V shape: (batch, seq_len, num_heads, head_dim)
#### **4A.2 RoPE 应用于 Q 和 K**
很关键：  
**RoPE 不作用于 V，只作用于 Q 和 K。**
#### **4A.3 Attention score**
`score = Q • K^T / sqrt(head_dim)`
注意：
- 对每个 head 独立算
- 复杂度 O(n²)
- decode 阶段利用 KV Cache 降低到 O(n)
#### **4A.4 Mask 处理**
##### **Causal Mask（因果mask）**
保证语言生成不可看未来：
`positions > current_pos → -∞`
##### **Padding Mask**
忽略 pad token。
#### **4A.5 Softmax 得权重**
`A = softmax(score)`
#### **4A.6 与 V 加权求和**
`attention_output = A * V`
#### **4A.7 合并多头**
`Concat(head_1, ..., head_h) W_O`
### 🔥 **4A+. KV Cache** 
[KV Cache介绍](../Transformer/KV%20Cache介绍.md)
推理 decode 阶段：
- 每步只输入一个 token
- Q 来自当前 token
- K/V ⽣成后 append 到 cache
- Attention 时不再计算完整序列

KV Cache 显著加速：
- 原 O(T²) → 变为 O(T)

这是大模型推理能实时生成的关键优化。
### **4B. Feed-Forward Network（FFN）**
[FFN与MLP介绍](../Transformer/FFN与MLP介绍.md)
**常见结构：**
`FFN(x) = W2 * GELU(W1 * x)`
扩展倍数：
- GPT-3 → 4 倍
- LLaMA → SwiGLU (8/3 倍)
激活：
- GELU
- SwiGLU（更稳定）
### **4C. LayerNorm + Residual**
Pre-LN（主流）：
`y = x + Attention(LN(x)) z = y + FFN(LN(y))`

优点：
- 更稳定
- 更好训练深层 Transformer

## **5. Output Projection（词表概率）**
### **5.1 最后线性层（LM Head）**
将 hidden state 映射到 vocab 大小：
`logits = hidden @ W_vocab^T`
### **5.2 Softmax 得到概率**
`probs = softmax(logits)`
## **6. Decoding（解码策略）**
### **6.1 Greedy**
直接取概率最大 token  
缺点：机械、重复
### **6.2 Sampling**
按概率抽样  
更自然
### **6.3 Top-k**
只在前 k 个 token 中挑选
### **6.4 Top-p（核采样）**
累积概率 > p 的最小集合中采样  
质量更好
### **6.5 Beam Search**
用于翻译，但不用于开放生成
推理系统常结合：
`top-p + temperature + min_p`
最终得到下一个 token。
## **7. 模型继续推理下一个 token**
### 每个 step：
1. 使用前一步生成的新 token
2. 从 KV Cache 中读取历史 K/V
3. 仅计算新的 Q/K/V
4. 更新 KV Cache
5. 输出下一个 token
### 流程：
`token → embedding → QKV → attention → logits → sample → next token`
直到：
- 遇到 `<eos>` 或
- 达到生成上限
## **8. 后处理（Postprocessing）**
- detokenize → 转成文字
- 去掉模板
- 清理特殊 token
## **9. 最终输出用户可阅读的文本**

## 📌 **总结：一个 token 是如何生成的？（极简）**

**一行话总结大模型推理：**

> 把输入文本切成 token，逐层用自注意力计算上下文关联，结合 KV Cache 加速，只用当前 token 的 Q 与历史 K/V 交互，再通过解码策略选择下一个 token。
