# 一、模型加载整体流程
大模型（10B～1T 参数）加载通常包括以下阶段：
## 1. 解析配置（config）
- 读取 `config.json` 或等价结构定义文件
- 包含模型层数、隐藏维度、注意力头数、词表大小等
- 不包含参数值（仅结构）
## 2. 构建模型结构（模型实例化）
- 根据 config 构建模型的层级结构
- 若使用 **Lazy Init / Meta Tensor**，此阶段不实际分配权重内存
- 仅创建张量的 metadata（shape、dtype）
## 3. 准备权重文件
权重可能是以下任意格式：
- 单文件 checkpoint（小模型）
- 多文件 **Sharded Checkpoint**
- safetensors / bin / pth / ckpt 等格式

文件组织可能是按层、按设备、按张量切分。
## 4. 按需从文件加载权重
加载策略取决于资源：
- 直接 load 到 CPU
- 使用 mmap 映射（按需调入）
- load 后按 device_map 分发到各 GPU
- 若使用量化权重，则同时进行 FP32→INT8/INT4 转换
## 5. 权重分配到最终设备（GPU / CPU）
通常有以下方式：
- 单 GPU：全部放入一张卡
- 多 GPU：按 device_map / tensor parallel 切分
- CPU/offload：部分层放在 CPU
- 混合：KV Cache 在 GPU, 模型部分在 CPU
## 6. 校验权重
- 检查 missing keys、unexpected keys
- 检查 shape 是否匹配
- 检查 dtype 是否一致
- 运行一次 dummy forward（可选）
## 7. 进入推理或训练模式
- 设置 eval()：从 训练 切换到 推理
- 关闭梯度（`torch.no_grad()` / `requires_grad=False`）：推理不需要计算梯度且防止意外修改权重
- 分配 KV Cache
- 准备 tokenizer 等辅助组件

上述流程在实际执行时，会根据资源选择不同加载方式，而这正是下面三项技术需要发挥作用的地方。

## 二、大模型加载的三项关键技术
## 1. Lazy Init / Meta Tensor（延迟初始化 / 元张量）

### 核心机制

初始化模型结构时，不创建实际张量数据，仅创建张量的 metadata：

- shape
    
- dtype
    
- device (meta)
    

示例：

`torch.empty((4096, 4096), device="meta")`

此时不占 RAM 或显存。

### 解决的问题

- 避免模型实例化阶段分配巨量内存
    
- 允许在不知道权重最终所在设备前构建模型
    
- 为大模型的分片加载提供基础
    

### 优点

- 启动内存峰值极低
    
- 模型结构可以非常大
    
- 与 device_map 结合可按 GPU 精细分配权重
    

### 局限

- 自定义层必须能提前推断出 weight shape
    
- 部分初始化逻辑需要重写
    
- 多 GPU 权重分配逻辑更复杂
    

---

## 2. Sharded Checkpoint（分片权重）

### 核心机制

将模型权重拆成多个文件而不是一个大 checkpoint，例如：

`pytorch_model-00001-of-00005.bin pytorch_model-00002-of-00005.bin`

或按 GPU：

`layer0-gpu0.pt layer0-gpu1.pt ...`

### 解决的问题

- 超大模型无法全部 fit 到单 GPU / 单文件
    
- 加快加载速度（可以并行 I/O）
    
- 使多 GPU 分布式权重分配更加自然
    

### 优点

- 文件更小，易管理
    
- 支持并行读取
    
- 支持多 GPU 分布式加载
    
- 可线性扩展（更多 GPU → 更大模型）
    

### 局限

- shard 文件数量可能非常多
    
- 分布式训练恢复逻辑较复杂
    
- 跨 GPU 的通信成本增加（尤其 ZeRO-3）
    

---

## 3. Memory Mapping（mmap）

### 核心机制

将权重文件映射到虚拟内存，不一次性读入 RAM：

`torch.load(path, mmap_mode='r')`

访问到某个张量时操作系统才从磁盘加载对应部分。

### 解决的问题

- 无需在加载阶段占用大量 RAM
    
- 支持大于本机 RAM 的权重文件
    
- 加载速度快（跳过完整读取）
    

### 优点

- 极低 RAM 使用
    
- 对于大模型启动速度快
    
- 对推理非常友好（权重访问具有较强顺序性）
    

### 局限

- 随机访问性能受磁盘读取速度影响
    
- 依赖 SSD/HDD 性能
    
- 访问模式（顺序或随机）可能影响推理速度
    

---

## 三、三项技术的组合方式

现代大模型加载并不单独使用某一种技术，而是组合使用：

### 1. Lazy Init + Sharded Checkpoint

（构建结构 + 从 shard 精确加载到每个设备）

流程：

1. 用 Meta Tensor 创模型结构（不占内存）
    
2. 根据 device_map 计算每个张量属于哪个设备
    
3. 只从对应 shard 加载必须的部分
    
4. 按需分配到 GPU/CPU
    

### 2. Sharded Checkpoint + mmap

（分片文件 + 按需调入）

流程：

1. 每个 shard 用 mmap_mode 打开
    
2. 访问相关权重时 OS 从文件读入
    
3. 实际 RAM 占用很小
    

适合本机 RAM 远小于权重大小的情况。

### 3. Lazy Init + mmap

（结构不占内存，权重按需读入）

流程：

1. 使用 Lazy Init 构建空壳模型
    
2. 权重使用 mmap 映射
    
3. 在 forward 过程中按需调入权重
    

非常适合超大模型推理。

---

## 四、整体整合图（步骤 + 技术）

         `解析配置(config)                 ↓      [Lazy Init 构建结构，不占内存]                 ↓     识别 shard 文件（Sharded Checkpoint）                 ↓   使用 mmap 映射 shard（不加载到 RAM）                 ↓   按 device_map 把权重加载到 GPU/CPU                 ↓          校验权重 shape/dtype                 ↓    设置推理模式（eval/no_grad）                 ↓            执行推理/训练`

---

# 总结（一句话版本）

- **Lazy Init / Meta Tensor**：构建模型结构不分配内存
    
- **Sharded Checkpoint**：用多个分片文件存权重，适配多 GPU
    
- **mmap**：权重按需从磁盘读取，不占 RAM
    

这三者共同支撑现代大模型（10B～1T）的加载。
