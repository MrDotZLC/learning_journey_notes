## 1. 岗位背景理解

### 1.1 公司为什么做 LLM 软件栈？

**问题：为什么存储芯片公司开始进入大模型领域？**

回答：

大模型的发展正在改变计算系统瓶颈。

传统 AI 主要关注计算能力，例如 FLOPS，但是 LLM 推理阶段，尤其 Decode 阶段，性能越来越受到 Memory Wall 限制。

大模型推理链路：

```text
模型权重
    |
Memory
    |
计算单元
    |
输出Token
```

随着模型规模增加：

* 参数规模增长
* 上下文长度增加
* KV Cache 增长

导致数据搬运成为主要成本。

LLM 推理需要关注：

* Memory Bandwidth
* Cache效率
* 数据调度
* 存储层级

存储芯片公司的优势不是和 GPU 竞争算力，而是在：

> 计算 + 存储 + 数据移动优化方向形成软硬件协同。

---

## 2. 为什么 LLM 推理存在 Memory Bound？

### 2.1 Prefill 和 Decode 区别

**问题：为什么说 Decode 阶段是 Memory Bound？**

回答：

LLM 推理分为两个阶段：

### Prefill

输入完整 Prompt。

特点：

* 一次处理大量 Token
* GEMM计算量大
* 数据复用率高

主要瓶颈：

Compute Bound。

### Decode

逐 Token 生成。

每生成一个 Token，需要访问：

* 当前 Query
* 历史 Key
* 历史 Value

即：

```text
Q_new

+
K_1...K_n

+
V_1...V_n
```

随着上下文增长：

$$
KVCache \propto SequenceLength
$$

访问数据越来越多。

判断瓶颈：

$$
AI=\frac{FLOPs}{MemoryBytes}
$$

当 Arithmetic Intensity 较低时：

性能主要受 Memory Bandwidth 限制。

## 3. 如果设计面向 LLM 的芯片，需要关注什么？

### 3.1 芯片架构方向

**问题：如果让你设计一颗面向 LLM 推理的芯片，你认为重点在哪里？**

回答：

重点不是单纯增加 TOPS，而是优化数据流。

主要方向：

### 1. Memory Hierarchy

典型层级：

```text
Register

↓

SRAM

↓

HBM

↓

DDR

↓

SSD
```

不同数据应该放在不同层级。

例如：

| 数据         | 位置       |
| ---------- | -------- |
| 正在计算的数据    | SRAM/HBM |
| 近期KV Cache | HBM/DDR  |
| 长期历史数据     | SSD      |

---

### 2. KV Cache 管理

KV Cache 是长上下文场景的主要内存压力。

优化：

* KV Cache Quantization
* Paged KV Cache
* Offloading
* Compression

---

### 3. 数据移动优化

性能瓶颈越来越来自：

```text
Data Movement
```

而不是：

```text
Compute
```

因此需要：

* 高带宽互联
* 数据预取
* Cache优化

---

## 7. Attention 和 FlashAttention

### 7.1 为什么FlashAttention快？

回答：

普通Attention：

需要保存：

$$
QK^T
$$

空间复杂度：

$$
O(N^2)
$$

FlashAttention：

采用：

* Tiling
* Online Softmax
* SRAM复用

核心：

减少：

HBM访问次数。

不是减少计算量，而是减少数据移动。

---

## 8. KV Cache优化

### 8.1 KV Cache为什么占显存？

回答：

每层保存：

* Key
* Value

大小：

$$
Memory=
2 \times Layers \times SeqLen \times Heads \times HeadDim \times Bytes
$$

影响因素：

* 模型层数
* 上下文长度
* Batch大小

---

### 8.2 如何优化KV Cache？

#### 方法1：量化

FP16：

2 Bytes

INT8：

1 Byte

减少约50%存储。

---

#### 方法2：PagedAttention

传统：

```text
连续Memory

Request1

Request2
```

问题：

碎片。

Paged：

```text
Page1

Page2

Page3
```

类似虚拟内存管理。

优势：

* 动态分配
* 降低碎片

---

#### 方法3：KV Cache Offload

分层：

```text
HBM

↓

DDR

↓

SSD
```

热数据：

高速Memory。

冷数据：

低速Memory。

关键：

通过：

* Prefetch
* Async IO
* Compression

隐藏延迟。

---

```text
↓

↓
```


价值：

利用已有生态，同时发挥存储优势。

## 15. 面试定位总结

对于存储芯片公司的LLM工程师岗位，核心能力不是：

“会写CUDA Kernel”。

而是：

> 理解LLM推理的数据流特点，并能够连接模型、Runtime、算子和存储硬件，实现软硬件协同优化。

个人定位：

```text
LLM推理系统工程师

+

CUDA Kernel优化能力

+

C++ Runtime开发能力

+

Memory优化意识
```

这是与Intel、Micron、西部数据背景技术团队更匹配的方向。
