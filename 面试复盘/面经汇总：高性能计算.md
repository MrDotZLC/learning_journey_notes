## 介绍 roofline
答：**实测算术强度 $I_{\text{actual}}$**

$$I_{\text{actual}} = \frac{\text{实际执行 FLOPs（FMA 指令数} \times 2\text{）}}{\text{实际 HBM 访问字节数}}$$
**计算 Roofline 脊点 $I^*$**

$$I^* = \frac{P_{\text{peak}}}{BW_{\text{HBM}}}$$

以 H100 SXM5 为例（FP16，非稀疏模式）：

$$I^*_{\text{H100}} = \frac{1979\ \text{TFLOPS}}{3.35\ \text{TB/s}} \approx 591\ \text{FLOP/Byte}$$

## 怎么解决 compute-bound？
如果计算单元利用率已经较高，则重点考虑 SIMD/SIMT 向量化、增加 ILP、优化线程映射、使用硬件矩阵乘单元、减少 instruction overhead，以及选择更适合硬件的计算精度。

## 怎么解决 memory-bound？
如果 profiling 发现 Arithmetic Intensity 较低、带宽利用率高而计算单元利用率低，我会优先优化访存，包括连续访问、coalescing、cache reuse、tiling、减少 global memory traffic、避免重复加载，以及必要时进行 operator fusion。

## CPU 和 GPU 在优化上的异同
CPU 和 GPU 优化的共同点是都要先通过 Profiling 定位瓶颈，再针对计算、访存、并行度和同步开销进行优化；

区别主要来自硬件架构，CPU 是少量强计算核心，更关注 Cache Locality、SIMD、Branch Prediction、Instruction-Level Parallelism 和线程同步，例如通过 Cache Blocking、数据布局和 AVX 向量化提高性能；

GPU 是大量并行计算单元，更关注 Thread/Block/Warp 的并行映射、Global Memory Coalescing、Shared Memory 数据复用、Register Pressure 和 Occupancy，例如通过 Tiling、Shared Memory、Warp-level Optimization 和 Kernel Fusion 提高吞吐。

因此 CPU 优化更偏向降低单线程延迟和提高 Cache/指令执行效率，GPU 优化更偏向提高大规模并行吞吐和隐藏 Memory Latency。

## 介绍SIMT和SIMD
SIMD（Single Instruction Multiple Data）和 SIMT（Single Instruction Multiple Threads）都是通过并行执行提高吞吐的方式，核心思想都是让一条指令同时处理多个数据，但执行模型不同：

SIMD 通常是 CPU 的向量化机制，一条向量指令作用于一个线程中的多个数据，例如 AVX2 的 256 bit 寄存器可以同时处理 8 个 FP32；

SIMT 是 GPU CUDA 的核心执行模型，一个 Warp 通常包含 32 个 Thread，线程各自拥有独立的寄存器和执行上下文，但硬件以 Warp 为单位执行相同的指令，因此可以理解为“多个线程协同执行同一条指令”。

两者的主要区别是 SIMD 强调“一个线程处理多个数据”，SIMT 强调“多个线程处理多个数据”；
当 SIMD/SIMT 中出现分支时，SIMD 通常需要通过 Mask 控制不同 Lane，GPU 的 SIMT 则会发生 Warp Divergence，同一个 Warp 中不同线程走不同分支时需要串行执行不同路径，因此都会受到分支不一致带来的性能影响。

## 为什么访问 Cache 比 DRAM 快？
答：因为 Cache 距离计算单元更近、容量更小、访问延迟更低；优化的核心就是提高数据局部性，让热点数据尽量停留在更高层级的存储中，从而减少高延迟 DRAM 访问。
