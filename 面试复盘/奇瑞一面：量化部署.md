## 模型量化与轻量化

### 1. 一个目标检测模型从 FP32 转为 INT8 后，检测精度明显下降，你怎么处理？
答：
1. 固定基线：同一数据集、预处理、输入 Shape、后处理与评估指标
2. 定位误差阶段：模型导出 → FP32 引擎 → FP16 → INT8 → 后处理
3. 定位敏感层：比较中间激活、权重误差、层输出误差与任务指标
4. 调整量化策略：优化校准集、量化粒度、校准算法，必要时保留敏感层高精度
5. 回归验证：任务精度、分场景指标、端到端延迟和内存占用

校准集不能只随机抽取少量容易样本，应覆盖白天、夜间、雨雾、远距离小目标、遮挡、不同曝光以及行车和泊车场景。对自动驾驶感知而言，整体 mAP 下降很小，也不代表安全关键类别、远距离目标或特定场景没有显著退化。

### 2. PTQ 和 QAT 怎么选？
答：核心权衡：**部署效率 vs 精度**。

| 维度 | PTQ | QAT |
| :--- | :--- | :--- |
| 原理 | 少量校准数据直接量化 | 训练时模拟量化误差，主动适应 |
| 精度 | Int4 及以下明显下降 | 损失极小，极低比特也稳 |
| 成本 | 低，几十分钟到几小时 | 高，约原始训练 10% 时间 |
| 数据 | 少量无标签样本 | 完整带标签数据集 |
| 适用 | Int8、简单模型、赶时间、数据受限 | Int4-、复杂模型（LLM/ViT）、精度要求极高 |

**选择建议：**
- **优先 PTQ**：Int8、常规 CNN、快速部署、数据拿不到。
- **必须 QAT**：Int4 及以下、Transformer 类复杂模型（Softmax/GELU 分布难拟合）。
- **折中**：混合量化（只对敏感层 QAT）或 PTQ + LoRA 微调补偿。

**一句话：赶时间、Int8、简单模型 → PTQ；极致压缩、复杂模型、有数据有算力 → QAT；想折中 → 混合量化。**

### 3. 为什么 INT8 量化后精度下降？
答：INT8 量化后精度下降，根本原因在于**用 8 位整数去近似原本高精度的浮点数时，引入了两类不可逆的误差：量化误差和截断误差**。

**① 量化误差（舍入误差）**  
每个浮点值被舍入到最近的整数格点，误差最大可达 S/2。当 SS 较大（即量化范围宽）时，单个值的误差就大。

**② 截断误差（Clipping Error）**  
这是精度下降更致命的原因。校准数据无法覆盖推理时所有可能的激活值。如果某个激活值超出了校准得到的 \[min,max]\[min,max] 范围，就会被硬截断到边界，产生巨大误差。例如校准范围是 \[-5, 5]，推理时出现 8.0，就会被截成 5.0。

### 4. 为什么神经网络对误差敏感？——误差会累积放大
答：
单层的一个小误差不可怕，可怕的是它在网络中传播放大：
- **逐层累积**：第 1 层的量化误差传到第 2 层，与第 2 层自身的量化误差叠加，再经过激活函数、残差连接等，逐层放大。
- **激活值分布复杂**：ReLU 后的激活值往往有长尾（少数极大值），Softmax/GELU 输出分布更复杂。用统一的 Scale 去量化，要么长尾被截断，要么主体部分分辨率不足。
- **权重与激活同时量化**：权重和激活都量化时，矩阵乘法的误差是两者误差的耦合，比只量化权重严重得多。

### 5. 哪些因素会加剧精度下降？
答：

| 因素              | 影响                             |
| --------------- | ------------------------------ |
| **模型本身冗余度低**    | 小模型、已剪枝模型对量化更敏感                |
| **激活值动态范围大**    | 如 Transformer 中的注意力输出，长尾严重     |
| **逐层独立校准**      | 未考虑层间误差传播，容易累积                 |
| **校准数据不具代表性**   | 截断误差增大                         |
| **对称量化 vs 非对称** | 对非对称分布（如 ReLU 后全正）用对称量化会浪费一半格子 |

### 6. 为什么有时 INT8 几乎不掉精度？
答：如果模型冗余度高、激活分布集中、校准数据充分，INT8 的 256 个格子足以较好近似，精度损失可控制在 1% 以内。这也是为什么 INT8 PTQ 在常规 CNN 上通常“够用”，而到了 Int4 或复杂 Transformer 上就必须上 QAT——因为格子太少，误差累积效应压不住了。

### 7. 如何缓解 INT8 精度损失？
答：更好的校准、非对称量化、逐通道量化、混合精度（敏感层保 FP16），以及 QAT 让模型主动适应这些误差。

### 8. MinMax 、 Entropy 校准和 Percentile 校准 有什么区别？
答：
**MinMax 校准**直接取激活值的全局最大最小值作为量化范围，简单快速且不产生截断误差，但容易被少数离群值“撑大”范围，导致主体分布的量化粒度太粗。它更适合激活分布集中、无明显长尾或者长尾不可丢弃的场景，如 NLP 任务和部分点云检测模型。点云检测模型特点是分布稀疏且带长尾。NLP 任务每一层都因为 softmax 和 残差 可能导致重尾分布，截断影响层语义表达，可以用 Per-channel 配合 MinMax。

**Entropy 校准**通过最小化量化前后的 KL 散度来寻找最优截断阈值，主动舍弃极端离群值，把有限的量化格子留给主体分布，从而降低整体信息损失，但计算复杂度更高。它更适合 CNN 视觉任务等激活值有明显长尾的模型，其长尾大部分是多层ReLU和卷积平滑后仍存在的噪声，截断后的损失小。

**Percentile 校准**通过统计激活值的分布直方图，去掉最极端的若干百分位数据（如 0.1% 或 1%），取剩余数据的最大值作为量化阈值。它本质上是 MinMax 和 Entropy 之间的**手动调节版本**：既不像 MinMax 那样保留所有离群值，也不像 Entropy 那样通过 KL 散度自动搜索最优截断点，而是由人工指定保留比例。其效果高度依赖百分位选择，99% 分位可能等价于 MinMax，而 80% 分位则可能过度截断导致精度骤降。在多数网络实验中，**99.9% 的 Percentile 反而会损害精度**，最佳策略通常是 Entropy 或 99.99%/99.999% 的 Percentile

### 9. 怎么找出敏感层？
答：

**方案一**：基于逐层误差的实测（最可靠，成本高）
只把某一层替换成量化版本，其余层保持浮点，观察模型输出的变化。常用指标为 MSE、MAE、余弦相似度。最接近 ground truth，但需逐层跑前向，成本较高。注意：MAE 对离群值不敏感，余弦相似度只看方向忽略幅度。

**方案二**：基于二阶信息的理论代理（理论扎实，需谨慎）
用参数二阶信息估算量化扰动对 loss 的影响。核心指标为 Hessian 迹、Fisher 信息矩阵（Hessian 近似）。依赖模型收敛假设，跨层比较可靠性存疑，在 TinyViT 等新架构上召回率可能很低。使用前建议在目标模型上做小规模验证。

**方案三**：基于激活分布形态的统计代理（快速，工具内置）
直接分析激活统计特征。linear 层常用 kurtosis（默认首选）、std、quantile；峰度越高量化风险越大，标准差易被离群值带偏，常配合 quantile 使用。计算成本极低，适合快速初筛。

**方案四**：基于分布散度的代理（跨架构最稳）
对比量化前后激活分布的差异，常用 KLD、JSD。跨架构评测中召回率显著优于曲率和权重类方法，JSD 比 KLD 更稳（对称、有界）。适合追求更准排序时使用。

**实操建议**
1. **快速初筛**：用工具内置统计指标（峰度/quantile）跑一遍，拿到 Top-15 候选层。
2. **追求更准排序**：考虑 JSD/KLD 类分布散度指标。
3. **最终把关**：任何代理指标都不能替代端到端精度验证。敏感度高 ≠ 回退后一定涨点，先选 Top-K 候选，逐批做端到端对比，再固化配置。

### 10. INT4 一定比 INT8 快吗？
答：**INT4 不一定比 INT8 快，取决于瓶颈在哪。**

**理论优势（内存瓶颈时成立）**
- 大模型单用户解码时，瓶颈是把权重从显存搬进计算单元，不是算力。
- INT4 每参数 0.5 字节，INT8 是 1 字节，数据搬运量减半。
- 实测 Batch 1 解码：INT8 约 2 倍加速，INT4 约 4 倍，基本与数据量成正比。

**可能更慢的原因**
- **瓶颈转移**：在大 Batch 或 Prefill 等计算瓶颈场景，减少数据量没用，瓶颈是算力。
- **解压开销**：INT4 数据压缩很密，GPU 算之前要先拆包还原，这个额外开销可能拖慢速度。有测试中某 AMD 显卡的 INT4 内核需先解压成 BF16 再算，反而成了负优化。
- **生态差异**：INT8 优化内核成熟稳定；INT4 依赖硬件和框架（如 TensorRT-LLM、vLLM）是否有专门优化算子，缺了就兑现不了优势。
- **精度代价**：INT4 只有 16 个离散值（INT8 有 256 个），量化误差大，生成任务上更容易精度骤降。

**决策建议**
- 追求极致显存压缩、单用户或低并发解码、且硬件框架支持 INT4 优化 → 选 INT4。
- 模型能塞进显存、或高并发吞吐、求稳定通用 → 选 INT8 更稳妥。
- 最终结论：最好在自己的任务和硬件上实测 Prefill 和 Decode 两个阶段耗时。

### 11. 剪枝后为什么延迟没有下降？
答：剪枝后延迟没下降，是模型压缩里非常常见的现象。核心原因在于：**剪枝减少的是“参数数量”或“理论计算量”，但硬件实际跑得快不快，取决于它能不能高效地“跳过”这些被剪掉的部分。**

- **非结构化剪枝**：只省存储，不省时间。硬件仍按密集矩阵加载计算，零值不会被跳过，计算量没变。
- **结构化剪枝**：理论上能跳过计算，但延迟常被其他因素隐藏，原因有三：
    1. **策略与硬件错位**：宽度剪枝层数没变，内核启动固定开销没省；层剪枝才能真正减少串行操作。
    2. **硬件利用率下降**：矩阵变小后喂不饱 GPU，计算量减半可能只换来很小延迟收益。
    3. **精度恢复拖累**：稀疏权重需解压还原，额外开销吃掉理论收益。
- **缺稀疏内核**：硬件和框架不支持对应稀疏模式（如 NVIDIA 2:4），就还是按密集算，延迟不变。

**排查顺序**：剪枝类型 → 稀疏模式是否匹配硬件 → 框架是否启用稀疏内核 → 区分 Prefill/Decode。

### 12. 蒸馏和量化可以一起使用吗？
答：**可以，而且很常见。** 蒸馏和量化是正交的两种压缩手段，解决不同问题，组合使用往往能兼顾效果和效率。

**两者分工**
- **蒸馏**：让小的“学生模型”模仿大的“教师模型”的输出或中间特征，目的是**用更少参数达到接近大模型的效果**。它改变的是模型结构和参数量。
- **量化**：把权重/激活从 FP16 降到 INT8、INT4 等低比特，目的是**减少存储和带宽、加速推理**。它改变的是数值精度，不改变结构。

两者作用维度不同，因此可以叠加：先蒸馏得到一个更小的学生模型，再对它量化，得到“又小又低比特”的模型。

**常见的组合顺序**
1. 先蒸馏，后量化（最主流）
	- 先训好小模型，再对权重做 PTQ（训练后量化）或 QAT（量化感知训练）。
	- 优点：流程清晰，蒸馏和量化各自独立调优。
	- 缺点：蒸馏时没考虑量化误差，量化后精度可能掉得比预期多。

2. 蒸馏时就把量化纳入训练（量化感知蒸馏）
	- 在蒸馏阶段就模拟量化误差，让学生模型学到的表示对低比特更鲁棒。
	- 典型做法：学生模型前向时插入伪量化节点，用教师的软标签 + 量化误差一起指导。
	- 优点：最终低比特精度通常更好。
	- 代表工作：QAT 与 KD 结合的各类方法（如 Quantized Distillation、LSQ-KD 等）。

3. 先量化教师，再蒸馏
	- 先把大教师量化，再用它指导学生。好处是教师推理成本低，适合教师本身太大、蒸馏开销高的场景。
	- 风险：量化教师输出有偏差，可能把噪声传给学生。

**实际要注意的点**
- **精度叠加损失**：蒸馏本身有精度损失，量化再损失一次，两者叠加可能超出预期。需要分别评估，别假设“1+1=2”。
- **顺序影响结果**：先蒸馏后量化 vs 量化感知蒸馏，最终精度可能差不少，通常后者更优但实现更复杂。
- **硬件收益看量化**：蒸馏减少的是参数量和 FLOPs，量化减少的是字节数和带宽。延迟收益主要来自量化，尤其在 Decode 这种内存瓶颈阶段。
- **框架支持**：PyTorch、TensorRT-LLM、vLLM 等对 QAT + KD 的支持程度不同，落地前要确认工具链。

**一句话：可以一起用，主流是“先蒸馏再量化”，追求极限低比特时用“量化感知蒸馏”效果更好，但精度损失要单独评估。**

### 13. TensorRT 支持的量化方案
答：
**支持的数据类型**
INT8、FP8 (E4M3)、INT4（仅权重）、FP4 (E2M1)。

**两种量化流程**
* **隐式量化（已弃用）**：仅支持 INT8。TensorRT 构建器自动决定哪些层量化，通过校准或 `setDynamicRange` API 提供 scale。
* **显式量化（推荐）**：模型中包含 Q/DQ 节点，精确控制量化的位置和精度。支持 INT8、FP8、INT4、FP4。

**量化粒度**
* **Per-tensor**：整个张量共用一个 scale。
* **Per-channel**：沿指定轴广播 scale（卷积通常是输出通道轴），仅用于权重。
* **Block**：张量按固定大小分块，每块独立 scale，支持 INT4 权重和 FP4 权重/激活。

**特殊方案**
* **Weight-Only Quantization (WoQ)**：仅 INT4，仅用于 GEMM 层。权重 INT4 存储，读取后反量化，计算仍为高精度。
* **动态量化**：scale 在推理时根据输入计算，仅支持 block 粒度。

**硬件支持**
* INT8：任何支持 TensorRT 的 NVIDIA GPU。
* FP8：Hopper 及更新架构。
* FP4：Blackwell 及更新架构。

**一句话：TensorRT 支持 INT8/FP8/INT4/FP4，推荐用显式量化（Q/DQ），INT4 仅限权重，FP4 用于最新 Blackwell 硬件。**

### 14. TensorRT INT8 Calibration 原理
答：**本质**：离线估计每个 Tensor 的动态区间，确定 scale，在**截断误差**和**量化误差**之间取最优平衡。

**1. 为什么需要校准？**
- 量化公式：`x_int8 = round(x / s)`，其中 `s = T / 127, T=max(abs(x))`
- 权重是静态的，可直接统计；**激活值依赖输入，必须用校准数据估计区间 T**。

**2. 区间 T 的核心权衡**
- **T 过大（取真实最大值）**：无截断，但 scale 大 → 量化步长粗 → rounding error 大。
- **T 过小（主动截断）**：scale 小 → rounding error 小，但超出范围的值被截断，信息丢失。

**3. 校准流程**
1. 用校准数据跑 FP32 推理
2. 统计激活值直方图
3. 按所选校准算法估计最优区间
4. 算 scale：`s = T / 127`
5. 缓存 `tensor_name → dynamic_range`，重建 engine 无需重跑

**4. 四种校准算法对比**

| 算法               | 策略             | 特点                                         |
| :--------------- | :------------- | :----------------------------------------- |
| MinMax           | T = max(\|x\|) | 无截断，但对 outlier 敏感，rounding error 大         |
| Percentile       | T = P(p%)      | 显式忽略 outlier，简单稳定，p 需经验设定                  |
| **Entropy (KL)** | 最小化量化前后分布差异    | **TensorRT 默认推荐**，抗 outlier，保留高概率区域，精度通常最佳 |
| MSE              | 最小化平方误差        | 数值误差最小，但对 outlier 敏感，需自定义                  |

**5. 为什么校准能提精度？**
直接用真实最大值时，rounding error 往往主导。适度截断 → scale 变小 → 有效分辨率提升 → 总误差降低。

**6. INT8 精度下降常见根因**
激活长尾分布、极端 outlier、小数值密集、Softmax/LayerNorm/GELU 敏感。TensorRT 通常对敏感层保留 FP16/FP32（混合精度）。

**一句话：校准 = 用代表性数据估计各 Tensor 最优动态区间，平衡截断与量化误差来确定 scale。**

## 推理引擎与底层优化

### 1.
