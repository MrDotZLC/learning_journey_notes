## 准备

### 1. 一个目标检测模型从 FP32 转为 INT8 后，检测精度明显下降，你怎么处理？
答：
1. 固定基线：同一数据集、预处理、输入 Shape、后处理与评估指标
2. 定位误差阶段：模型导出 → FP32 引擎 → FP16 → INT8 → 后处理
3. 定位敏感层：比较中间激活、权重误差、层输出误差与任务指标
4. 调整量化策略：优化校准集、量化粒度、校准算法，必要时保留敏感层高精度
5. 回归验证：任务精度、分场景指标、端到端延迟和内存占用

校准集不能只随机抽取少量容易样本，应覆盖白天、夜间、雨雾、远距离小目标、遮挡、不同曝光以及行车和泊车场景。对自动驾驶感知而言，整体 mAP 下降很小，也不代表安全关键类别、远距离目标或特定场景没有显著退化。

### 2. PTQ 和 QAT 怎么选？
答：
选择 PTQ 还是 QAT，核心是在 **“部署效率与成本”** 和 **“模型精度与稳定性”** 之间做权衡。没有绝对的最优解，关键看你的模型复杂度、比特宽度和手头资源。

| 对比维度 | PTQ（后训练量化） | QAT（量化感知训练） |
| :--- | :--- | :--- |
| **核心原理** | 用少量校准数据统计分布，直接量化已训练好的模型 | 训练时模拟量化误差，让模型主动学习适应低精度 |
| **精度表现** | 中低比特（如Int4及以下）下通常有明显下降，复杂模型尤其明显 | 精度损失极小，在极低比特下仍能保持较好性能 |
| **时间/算力成本** | 低。通常只需几十分钟到几小时，无需GPU重训 | 高。相当于一次完整的微调，通常需要原始训练10%左右的时间 |
| **数据需求** | 仅需少量无标签校准样本 | 需要完整的训练数据集（带标签） |
| **适用场景** | 对部署速度要求高、精度容忍度尚可；Int8通常够用；数据隐私受限 | 对精度要求极高（如医疗、自动驾驶）；Int4/Int2等极低比特；复杂模型（如Transformer） |

**1. 什么时候优先选 PTQ？**

如果你的量化目标是 **Int8**，或者模型是常规的 CNN，PTQ 通常是性价比最高的选择。它的流程极快，几乎“即插即用”，非常适合快速验证部署或精度要求不苛刻的场景。另外，当训练数据因隐私或版权问题无法获取时，PTQ 是唯一可行的路径。

**2. 什么时候必须上 QAT？**

当你把比特数压到 **Int4 甚至更低**，或者模型包含复杂的 Transformer 结构（如 LLM、ViT）时，PTQ 很容易“崩掉”。因为 Transformer 中的 Softmax、GELU 等激活值分布复杂，PTQ 的粗略统计很难拟合，此时 QAT 几乎是保证精度的必选项。虽然成本高，但它是实现 1-2 bit 极限量化的核心技术。

**3. 折中方案：混合量化或轻量 QAT**

如果你的资源有限，但又担心 PTQ 精度不够，可以考虑折中策略：
*   **混合量化 (PTQAT)**：只对少数敏感层做 QAT 微调，其余层保持 PTQ。有研究显示，冻结近 50% 的层，就能达到接近纯 QAT 的效果。
*   **PTQ 预量化 + LoRA**：先用 PTQ 得到一个不错的起点，然后仅用 LoRA 微调少量参数来补偿量化误差。这比全量 QAT 省显存得多，适合大模型。

总结一下：**赶时间、Int8、简单模型 → PTQ；追求极致压缩率（Int4-）、复杂模型、有数据有算力 → QAT；想折中 → 混合量化。**
