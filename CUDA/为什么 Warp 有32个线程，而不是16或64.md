## 一、为什么 **warp 是 32 线程**，而不是 16 / 64？
> **结论先行**：  
> 32 是在 **指令控制复杂度、访存带宽、延迟隐藏能力、功耗与面积** 之间的工程最优平衡点，而不是随意选的数。

### 1️⃣ Warp 的本质：SIMT 的最小调度单元
在 NVIDIA GPU 中：
- **warp = 同一条指令 + 同一 PC**
- warp 是 **调度、发射、分支收敛、屏蔽掩码** 的最小单位
- warp 内线程：
    - 指令锁步执行
    - 通过 active mask 控制是否生效
因此，warp 大小直接决定：
- 每条指令控制多少线程
- 每次发射消耗多少硬件资源
### 2️⃣ 为什么不是 16（太小）
#### (1) 延迟隐藏能力不足
GPU 通过 **切换 warp** 来隐藏延迟：
- 全局内存访问：~400–800 cycles
- 需要 **大量“就绪 warp”** 才能覆盖空泡
warp = 16：
- 每个 warp 能做的工作少
- 需要更多 warp 数量才能隐藏延迟
- warp 调度、状态维护成本显著上升
➡ **调度开销 / 计算比过高**
#### (2) 内存合并效率下降
现代 GPU 内存事务以 **cache line（128B）** 为核心：
- 32 × 4B（float）= 128B（完美对齐）
- warp = 16 → 64B → 访存带宽利用率下降
➡ **16 线程 warp 无法自然对齐主流访存粒度**
### 3️⃣ 为什么不是 64（太大）
#### (1) 分支发散代价急剧上升
warp 内如果有分支：
- 所有路径必须串行执行
- active mask 控制生效线程
warp = 64：
- 更容易出现“部分线程走不同分支”
- 发散概率随 warp 宽度 **非线性上升**
➡ **SIMT 效率显著下降**
#### (2) 寄存器与上下文成本过高
warp 的上下文包括：
- PC
- active mask
- predicate
- scoreboard 状态
warp = 64：
- 单 warp 状态更大
- SM 同时能驻留的 warp 数下降
➡ **占用率（occupancy）下降**
### 4️⃣ 为什么 32 是“甜点区间”

| 维度    | 16  | **32** | 64  |
| ----- | --- | ------ | --- |
| 延迟隐藏  | 不足  | **足够** | 足够  |
| 分支发散  | 低   | **可控** | 高   |
| 访存合并  | 差   | **完美** | 完美  |
| 调度复杂度 | 高   | **合理** | 高   |
| 工程成本  | 高   | **最低** | 高   |

> **32 是“既不过小，也不过大”的工程折中点**
