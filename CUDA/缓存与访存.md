# 一、整体访存与缓存层级总览（从线程到 DRAM）
## 1.1 GPU 存储与缓存层级（由近到远）
从 **线程指令** 发出一次 load/store 开始，可能经过以下层级：
```
Thread
 └─ Registers（寄存器）
     └─ L1 Data Cache / Shared Memory（每个 SM）
         └─ L2 Cache（全芯片共享）
             └─ HBM / GDDR DRAM（显存）
```
**关键点：**
- GPU 的缓存是 **SM 为中心** 而不是 CPU 的“核心 + 私有 cache”模式
- L1 与 Shared Memory 在物理上**高度耦合**
- L2 是 **统一缓存（Unified L2）**，所有 SM 共享
- CUDA 12.6 默认开启 **统一内存一致性模型（UVM + ATS 支持）**
# 二、逻辑存储模型（CUDA 程序员可见）
## 2.1 CUDA 的逻辑存储空间（Address Space）
CUDA 从语言层面定义了多种 **逻辑地址空间**：

|逻辑空间|访问主体|缓存位置|物理位置|
|---|---|---|---|
|Register|单线程|无 cache|SM 寄存器文件|
|Local|单线程|L1/L2|DRAM|
|Shared|Block|无 L1/L2|SM 内 SRAM|
|Global|所有线程|L1/L2|DRAM|
|Constant|所有线程|Constant Cache|DRAM|
|Texture|所有线程|Texture Cache|DRAM|
> CUDA 12.6 下，**global / local / unified memory** 都走统一的缓存层级（L1 + L2）
# 三、物理缓存结构（硬件实现）
## 3.1 SM 内部结构（核心）
一个 SM（Streaming Multiprocessor）包含：
```
SM
 ├─ Warp Schedulers
 ├─ Register File
 ├─ L1 Data Cache
 ├─ Shared Memory
 ├─ Load/Store Units
```
### 3.1.1 L1 Cache 与 Shared Memory 的物理关系
在 Ampere 及以后架构中：
- **L1 Cache 与 Shared Memory 共用一块 SRAM**
- 容量可配置（由编译器和驱动自动调度）
典型配置示例（Ampere）：
- 总 SRAM：192 KB / SM
- 可分配：
    - 128 KB Shared + 64 KB L1
    - 或反之
> CUDA 12.6 编译器会根据 kernel 的 shared usage、访存模式自动选择最优配置。
## 3.2 L1 Cache（SM 私有）

|属性|描述|
|---|---|
|作用范围|单个 SM|
|Cache Line|128B（按 sector 划分）|
|访问粒度|Warp 合并访问|
|缓存内容|Global / Local / Unified|
|一致性|对 SM 内线程一致|
**关键特性：**
- **非一致于其他 SM**
- 写策略为 **write-through 到 L2**
- 为高并发吞吐而非低延迟设计
## 3.3 L2 Cache（全芯片统一）

|属性|描述|
|---|---|
|作用范围|所有 SM|
|物理位置|芯片中央|
|容量|数 MB ～ 数十 MB（架构相关）|
|Cache Line|64B / 128B|
|一致性|全 GPU 一致|
**L2 的职责：**
- 跨 SM 数据共享
- 原子操作的最终一致点
- NVLink / PCIe 数据中转
- Unified Memory 的一致性维护
CUDA 12.6 中，**所有 global memory 原子操作都在 L2 完成仲裁**
# 四、一次 Global Memory Load 的完整流程
下面以 **一个 warp 执行 `ld.global` 指令** 为例，说明完整物理流程。
## 4.1 指令级流程（逻辑）
1. Warp 发出 load 指令
2. 编译器生成 `LDG` / `LD` 指令
3. Load/Store Unit 接管
## 4.2 Warp 级访存合并（Coalescing）
硬件在 SM 内执行：
- 将 warp 中 32 个线程的地址：
    - 对齐
    - 合并
    - 分组成若干 **memory transactions**
规则（简化）：
- 连续访问 → 1～2 个 128B transaction
- 离散访问 → 多个 transaction，性能急剧下降
## 4.3 L1 Cache 查询
```
Load Request
 └─ 查询 L1 Tag
     ├─ Hit → 返回数据
     └─ Miss → 发送到 L2
```
- 命中：~20 cycles
- Miss：进入片上互连
## 4.4 L2 Cache 查询
```
L2
 ├─ Hit → 返回到 SM
 └─ Miss → 访问 DRAM
```
- L2 命中：~100 cycles
- L2 未命中：~300–800 cycles
## 4.5 DRAM 访问（HBM/GDDR）
- Memory Controller 调度
- 行缓冲、bank 仲裁
- 数据回写到 L2
- L2 再返回 L1
- L1 提供给 Warp
# 五、Store（写操作）流程
## 5.1 写路径
```
Thread Store
 └─ L1（不保留脏数据）
     └─ 直接写入 L2
         └─ 延迟写回 DRAM
```
**特点：**
- L1 **不保持写回一致性**
- 所有写都在 L2 统一仲裁
- 原子操作 **必经 L2**
# 六、特殊缓存与访存通道
## 6.1 Constant Cache
- 只读
- Warp 内广播优化
- 适合所有线程访问同一地址
## 6.2 Texture Cache
- 针对二维/三维空间局部性
- 有地址重排与过滤单元
- 实际物理上仍在 L1/L2 体系中
# 七、Unified Memory（CUDA 12.6 重点）
## 7.1 地址统一
- CPU 与 GPU 共享虚拟地址
- 由 GPU MMU + ATS 实现
## 7.2 页迁移与缓存
```
Page Fault
 └─ 驱动介入
     └─ 数据迁移
         └─ 更新 L2 / TLB
```
- 页粒度：4KB / 64KB
- L2 是一致性核心
- CUDA 12.6 对 Hopper 支持 **Page Residency Tracking**
# 八、性能相关的核心总结
1. **访存优化本质是：**
    - Warp 合并
    - L1/L2 命中率
    - 隐藏 DRAM 延迟
2. **Shared Memory ≠ Cache**
    - 程序员显式管理
    - 低延迟、确定性
3. **L2 是 GPU 的一致性中枢**
    - 原子
    - UM
    - 多 SM 协作
# 九、逻辑—物理—流程三层对照总结表

| 层次  | 关注点  | CUDA 抽象         | 物理现实                |
| --- | ---- | --------------- | ------------------- |
| 逻辑  | 地址空间 | global / shared | DRAM / SRAM         |
| 物理  | 硬件单元 | SM / L2         | SRAM / HBM          |
| 流程  | 数据流动 | load/store      | tag → miss → refill |
