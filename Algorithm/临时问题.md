#### 1. 传入并修改裸指针，为什么要传入指针地址，即T**？
   答：C语言参数传递是**值传递**，T\*仅代表T指针的地址值，故函数会创建一个值副本，没有修改传入指针。如果要修改函数外的变量，需要传入T\*\*或智能指针引用
   
#### 2. struct和class的区别
   答：**struct** 和 **class** 唯一的语言层面区别是：
	- **struct** 默认成员和继承是 `public`。
	- **class** 默认成员和继承是 `private`。

#### 3. 原始数组、栈和堆的区别？
   答： 

| 特性 / 容器类型       | 原始数组 (`int a[3]`) | `std::array<int, 3>` | `std::vector<int>` |
| --------------- | ----------------- | -------------------- | ------------------ |
| **大小是否固定**      | 是                 | 是                    | 否，动态大小             |
| **是否支持动态扩容**    | 否                 | 否                    | 是                  |
| **是否支持赋值/拷贝**   | 否                 | 是                    | 是                  |
| **支持 STL 容器接口** | 否                 | 是                    | 是                  |
| **支持迭代器**       | 否                 | 是                    | 是                  |
| **访问越界检查**      | 无，易出错             | 有（`.at()` 抛异常）       | 有（`.at()` 抛异常）     |
| **内存分配位置**      | 栈上（或静态区）          | 栈上                   | 堆上                 |
| **自动管理内存**      | 否                 | 是                    | 是                  |
| **生命周期管理**      | 由作用域决定，无构造析构      | 由作用域决定，带构造析构         | 由对象管理，带构造析构        |
| **适用场景**        | 极限性能、C 兼容         | 固定大小、安全、STL 兼容       | 动态大小、灵活增删元素        |
| **性能开销**        | 最低，无封装            | 低，轻量封装               | 较高，动态内存分配          |
| **类型安全**        | 差                 | 高                    | 高                  |
| **易用性**         | 低，需要手动管理          | 高，易用                 | 很高，功能强大            |
#### 4. 自增前后置的区别
答：
- **对于内置类型：**
    - 编译器能识别 `i++` 其实并不需要保存旧值（如果旧值没被用到的话）。
    - 优化后，`i++` 和 `++i` 生成的机器码可以完全一致。
- **对于类类型：**
    - 编译器必须遵守语言语义，不能去掉拷贝（因为用户可能重载了复制构造函数，有副作用）。
    - 所以后置自增有本质额外的函数调用成本。
    - 前置自增避免了这个成本。

|类型|推荐用法|说明|
|---|---|---|
|内置类型|`++i` 或 `i++`|性能差异微乎其微，习惯用 `++i`|
|类类型（迭代器、自定义）|**优先 `++i`**|避免多余拷贝构造，提高性能|
#### 5. size_t a = 2，int b = -1，b > a为true？
答：int与size_t比较，int会转为无符号类型size_t，-1会转成4294967295，故直接使用size_t需要考虑其他变量是否会出问题。

#### 6. **“`std::function` 包裹 lambda”** 和 **“C++14 的 `self` 参数递归 lambda”** 两种写法的区别与优缺点

| 特性    | `std::function` 包裹    | `self` 参数递归     |
| ----- | --------------------- | --------------- |
| 语法直观性 | ✅ 简单，像普通递归            | ❌ 要传 `self`，稍微绕 |
| 性能开销  | ❌ 有额外开销（类型擦除 + 可能堆分配） | ✅ 无额外开销         |
| 内联优化  | ❌ 不容易内联               | ✅ 更容易内联         |
| 泛型支持  | ✅ 任意签名都行              | ⚠️ 模板写法复杂       |
| 适合场景  | 业务代码、性能要求不高           | 算法题、性能敏感逻辑      |
