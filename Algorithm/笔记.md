# 原始数组
![[Pasted image 20250711022215.png]]

## 知识
### 基础概念
1. int arr\[3\] = {10, 20, 30};
2. 数组是存放在连续内存空间上的相同类型数据的集合。
3. 数组下标都是从0开始的。
4. 数组内存空间的地址是连续的，增删可能会移动其他元素。
5. 数组元素只能覆盖，不能删！
6. 不能释放单一元素，只能全部释放

### 数组的存储
1. 原始二维数组是一维连续存储
2. `array`本质上就是一个封装了原始数组的结构体，不涉及动态内存分配，本身是连续存储的，其二维数组也是一维连续存储
3. `vector`的每一行独立存储，其二维数组非连续
4. `int**` 动态二维指针，不连续，每一行指向单独分配的数组，位置随机
5. `std::vector<std::array<int, 4>>`中每个`array`是连续的，整体也是连续

### 数组为什么不能释放单个元素？
- 原因 1：连续内存 + 统一分配，
  数组的所有元素是一次性整体分配的（无论在栈还是堆上）。
  操作系统或运行时不会允许你释放这片内存的一部分。
- 原因 **2**：释放机制只认“起始地址”
  `free(ptr)` 只能用于释放当初 `malloc` 返回的那个原始地址。
  指向数组中间某个元素的地址是非法释放行为。

### 释放部分内容的替代方法
1. 用结构记录“有效元素”范围
```
int* arr = malloc(100 * sizeof(int));
int size = 100;
int valid_size = 60;  // 实际只用前 60 个元素
```
2. 拆成多个小块
```
int* blocks[10];
for (int i = 0; i < 10; ++i)
    blocks[i] = malloc(10 * sizeof(int));

// 想释放第5块
free(blocks[5]);
```
### ==*拓展：栈与堆的对比==

| 特性     | 栈（Stack）    | 堆（Heap）             |
| ------ | ----------- | ------------------- |
| 分配方式   | 编译器自动分配     | 程序员手动分配（malloc/new） |
| 释放方式   | 自动释放（函数结束时） | 手动释放（free/delete）   |
| 分配速度   | 非常快         | 相对较慢                |
| 大小限制   | 有限（几MB）     | 取决于物理内存             |
| 地址空间   | 高地址向低地址增长   | 低地址向高地址增长           |
| 生命周期   | 与作用域绑定      | 控制权在程序员             |
| 可否动态扩展 | ❌ 不行        | ✅ 可以动态申请更大空间        |



# 链表
## 知识
一种通过指针串联在一起的线性结构，每一个节点由两部分组成，一个是数据域一个是指针域（存放指向下一个节点的指针），最后一个节点的指针域指向null（空指针的意思）。

```
// 单链表
struct ListNode {
    int val;  // 节点上存储的元素
    ListNode *next;  // 指向下一个节点的指针
    ListNode(int x) : val(x), next(NULL) {}  // 节点的构造函数
};

ListNode* head = new ListNode();
ListNode* head = new ListNode(5);
```

类型：单链表、双链表、循环链表

| 对比项   | 数组           | 链表              |
| ----- | ------------ | --------------- |
| 内存连续性 | ✅ 是          | ❌ 否             |
| 随机访问  | ✅ 快 (`O(1)`) | ❌ 慢 (`O(n)`)    |
| 插入删除  | ❌ 慢 (`O(n)`) | ✅ 快（`O(1)` 若定位） |
| 内存开销  | ✅ 低          | ❌ 高（需指针）        |
| 空间利用率 | ✅ 高          | ❌ 低（碎片+指针）      |
| 实现复杂度 | ✅ 简单         | ❌ 稍复杂（需指针）      |
| 扩容能力  | ❌ 需要重分配      | ✅ 不需重分配         |


# 哈希表
## 知识
	哈希表：根据关键码的值而直接进行访问的数据结构。数组就是以索引为关键码的哈希表。
	哈希函数：将关键码转换为对应值的函数。
	哈希碰撞：同一索引对应对个值，即哈希碰撞。解决办法：拉链法和线性探测法
常见的哈希结构：数组、set、map

| 集合                 | 底层实现 | 是否有序  | 数值是否可以重复 | 能否更改数值  | 查询效率     | 增删效率     |
| ------------------ | ---- | ----- | -------- | ------- | -------- | -------- |
| std::set           | 红黑树  | 有序    | 否        | 否       | O(log n) | O(log n) |
| std::multiset      | 红黑树  | 有序    | 是        | 否       | O(logn)  | O(logn)  |
| std::unordered_set | 哈希表  | 无序    | 否        | 否       | O(1)     | O(1)     |
|                    |      |       |          |         |          |          |
| 映射                 | 底层实现 | 是否有序  | 数值是否可以重复 | 能否更改数值  | 查询效率     | 增删效率     |
| std::map           | 红黑树  | key有序 | key不可重复  | key不可修改 | O(logn)  | O(logn)  |
| std::multimap      | 红黑树  | key有序 | key可重复   | key不可修改 | O(log n) | O(log n) |
| std::unordered_map | 哈希表  | key无序 | key不可重复  | key不可修改 | O(1)     | O(1)     |


# 字符串
在C语言中，把一个字符串存入一个数组时，也把结束符 '\0'存入数组，并以此作为该字符串是否结束的标志。

# 栈与队列
## 知识
栈：先进后出
队列：先进先出

	它们不是容器，是容器适配器。

栈是以底层容器完成其所有的工作，对外提供统一的接口，底层容器是可插拔的，用vector、deque、list都可以。
C++中，栈与队列的缺省底层容器为deque。

### 栈里的元素在内存中是连续分布的吗
答：不一定，栈不是容器，是容器适配器，其底层容器可能是vector，也可能是deque或list。如果是vector，则是连续的；其他两种则不是。

# 二叉树
## 知识

### 种类：
- 满二叉树：如果一棵二叉树只有度为0的结点和度为2的结点，并且度为0的结点在同一层上，则这棵二叉树为满二叉树。
![[Pasted image 20250714172738.png]]
- 完全二叉树：在完全二叉树中，除了最底层节点可能没填满外，其余每层节点数都达到最大值，并且最下面一层的节点都集中在该层最左边的若干位置。若最底层为第 h 层（h从1开始），则该层包含 1~ 2^(h-1) 个节点。
![[Pasted image 20250714172745.png]]

- 二叉搜索树：节点有数值且有序的树。
1. 若它的左子树不空，则左子树上所有结点的值均小于它的根结点的值；
2. 若它的右子树不空，则右子树上所有结点的值均大于它的根结点的值；
3. 它的左、右子树也分别为二叉排序树。
![[Pasted image 20250714173338.png]]
- 平衡二叉搜索树：又被称为AVL（Adelson-Velsky and Landis）树，且具有以下性质：它是一棵空树或它的左右两个子树的高度差的绝对值不超过1，并且左右两个子树都是一棵平衡二叉树。

# 回溯算法
回溯法也可以叫做回溯搜索法，它是一种搜索的方式。回溯是递归的副产品，只要有递归就会有回溯。
回溯的本质是穷举，穷举所有可能，可用剪枝提高效率。

![[Pasted image 20250714175722.png]]
回溯法解决的问题都可以抽象为树形结构（高度有限的N叉树），在集合中递归查找子集，集合的大小就构成了树的宽度，递归的深度就构成了树的深度。
```
回溯模板：

void backtracking(参数) {
    if (终止条件) {
        存放结果;
        return;
    }

    for (选择：本层集合中元素（树中节点孩子的数量就是集合的大小）) {
        处理节点;
        backtracking(路径，选择列表); // 递归
        回溯，撤销处理结果
    }
}
```

### 递归与回溯的对比

| 项目         | 递归           | 回溯                |
| ---------- | ------------ | ----------------- |
| 本质         | 函数调用自身       | 一种搜索策略（尝试 + 撤回）   |
| 是否一定需要     | 是            | 通常基于递归实现          |
| 是否包含撤销     | 否            | 是（回退一步换路径）        |
| 应用场景       | 分治、树结构、数学问题等 | 组合、排列、N皇后、数独、图搜索等 |
| 是否遍历所有可能路径 | 不一定          | 是（除非剪枝）           |
| 类比         | 下楼梯          | 走迷宫               |
