## 1. **量化（Quantization）**
### **概念**
量化是指 **把模型的权重、激活或者梯度从高精度（通常是 FP32）转换为低精度（FP16、INT8 等）**，从而减少内存占用和计算量。
### **类型**
1. **权重量化（Weight Quantization）**
    - 只量化模型的参数权重。
    - 常用：FP32 → FP16 或 INT8。
    - 优点：减少模型大小，推理加速。
    - 缺点：可能带来精度损失。
2. **激活量化（Activation Quantization）**
    - 对中间计算结果（激活）进行量化。
    - 推理速度提升更明显，因为计算量减少。
    - 通常和权重量化一起使用。
3. **动态量化 vs. 静态量化**
    - **动态量化**：推理时按 batch/输入动态量化激活。
    - **静态量化**：先通过校准数据集测量激活范围，再量化。
### **常见精度**

| 类型          | 精度    | 优点          | 缺点       |
| ----------- | ----- | ----------- | -------- |
| FP16        | 半精度   | 减少内存和带宽     | 精度略下降    |
| BF16        | 半精度   | 精度接近 FP32   | 硬件支持有限   |
| INT8        | 8 位整数 | 显存最小、速度最快   | 精度下降明显   |
| INT4 / INT2 | 超低精度  | 推理速度极快、存储最小 | 精度可能严重下降 |
|             |       |             |          |
### **应用场景**
- 推理优化：在 GPU/CPU/移动端减少延迟。
- 模型部署：大模型在显存受限的设备上运行。
- 高性能计算场景：数据中心或边缘设备推理。
## 2. **AMP（Automatic Mixed Precision）**
### **概念**
AMP 是 **自动混合精度训练（Automatic Mixed Precision Training）**，指在训练中 **部分计算使用 FP16/BF16，部分保持 FP32**，实现训练加速和显存节省，同时尽量不影响模型精度。
### **原理**
- **梯度累积和权重更新保持 FP32**，保证训练稳定性。
- **前向计算、反向传播的一些矩阵乘法用 FP16/BF16**，加速训练。
- NVIDIA 的 **Apex** 或 PyTorch 的 **torch.cuda.amp** 实现了 AMP。
### **特点**
- 自动混合：框架会根据运算类型选择使用 FP16 或 FP32。
- 动态损失缩放（Dynamic Loss Scaling）防止 FP16 下梯度下溢。
### **应用场景**
- 大模型训练（显存占用大）。
- GPU 训练速度优化。
- FP32 精度敏感的模型可以尝试 AMP。
## 3. **对比总结**

| 特性   | 量化（Quantization）         | AMP（混合精度）              |
| ---- | ------------------------ | ---------------------- |
| 主要用途 | 推理加速 / 减小模型大小            | 训练加速 / 减少显存            |
| 精度变化 | 可能明显降低（INT8/INT4）        | 几乎不降低，FP32 部分保持精度      |
| 适用阶段 | 推理 / 部署                  | 训练                     |
| 技术手段 | 将权重和激活从 FP32 → FP16/INT8 | 前向/反向部分计算 FP16，梯度 FP32 |
| 优点   | 显存小、推理快                  | 提升训练速度，节省显存            |
